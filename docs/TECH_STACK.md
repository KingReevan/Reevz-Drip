# Tech stack

Derived from **Reevz Mealz** (`../ReevzMealz`), which is a working, shipped-to-one-phone app on the
same toolchain. Reevz Drip inherits its stack wholesale. This document records what that stack is,
what the current scaffold already has, and what has to be added before the first real feature can
land.

## The stack, in one table

| Layer | Choice | Notes |
| --- | --- | --- |
| Language | Kotlin 2.2.10 | AGP 9 compiles it; no `kotlin.android` plugin |
| UI | Jetpack Compose, BOM 2026.02.01 | Material 3 |
| Architecture | MVVM | ViewModel + `StateFlow<UiState>`, no repository layer |
| Persistence | Room 2.8.4 + KSP | Local SQLite, schemas exported |
| Async | Kotlin coroutines + Flow | `Flow` out of DAOs, `stateIn` in ViewModels |
| DI | **None** | Manual construction via `viewModelFactory`. Deliberate. |
| Navigation | **None** | An `enum` of sections + Compose `when`. Deliberate. |
| Build | Gradle 9.5.0, AGP 9.3.3, version catalog | Configuration cache on |
| Min / target SDK | 24 / 37 | Target device: Nothing Phone (2a) |

### Things that are deliberately absent

Reevz Mealz ships without these, and Reevz Drip should not add them without the user asking:

- **No Hilt / Koin / any DI framework.** ViewModels are built by hand in a `companion object`
  `Factory`. For an app of this size DI is pure ceremony.
- **No Navigation-Compose / no `NavHost`.** Sections are an `enum class AppSection`, and the app
  shell renders the current one with a `when`. Back handling is explicit. This keeps the whole
  navigation model readable in one 60-line file.
- **No repository layer.** ViewModels talk to DAOs directly. A repository between a DAO and a
  ViewModel that adds no caching, no merging and no second data source is a file that exists to
  satisfy a diagram.
- **No backend, no auth, no analytics, no AI.** Offline-first, single user, single device.
- **No WorkManager.** Mealz schedules its one nightly reminder with `AlarmManager` +
  `BroadcastReceiver` + a `BOOT_COMPLETED` receiver to re-arm after reboot.

## What the scaffold already has

`ReevzDrip` was generated by Android Studio's Empty Compose Activity template and already matches
Mealz on the build side. Present and correct:

- `settings.gradle.kts`, wrapper on Gradle 9.5.0, `rootProject.name = "Reevz Drip"`, single `:app`.
- AGP 9.3.3 + `org.jetbrains.kotlin.plugin.compose`, no `kotlin.android` plugin.
- AGP 9 idioms already in place: `compileSdk { version = release(37) }`,
  `optimization { enable = false }`, `app/src/main/keepRules/rules.keep`.
- `org.gradle.configuration-cache=true`.
- Version catalog at `gradle/libs.versions.toml` with Compose BOM, Material 3, activity-compose,
  core-ktx, lifecycle-runtime-ktx, and the test deps.
- Package `com.reevan.reevzdrip`, `minSdk 24` / `targetSdk 37`.

The catalog is actually **cleaner than Mealz's**: Mealz declares `core-ktx 1.10.1` and
`lifecycle-runtime-ktx 2.6.1` but resolves to `1.18.0` / `2.9.4` through transitive constraints, so
its catalog lies. Drip declares `1.19.0` and `2.11.0` up front. Keep it that way — do not copy the
stale numbers across.

## Gap list — what must be added

Nothing below has been done. Each item names the phase that forces it.

### 1. Room + KSP — needed by the first phase that persists anything

`gradle/libs.versions.toml`:

```toml
[versions]
ksp = "2.2.10-2.0.2"     # must track kotlin = "2.2.10"
room = "2.8.4"

[libraries]
androidx-room-runtime  = { group = "androidx.room", name = "room-runtime",  version.ref = "room" }
androidx-room-ktx      = { group = "androidx.room", name = "room-ktx",      version.ref = "room" }
androidx-room-compiler = { group = "androidx.room", name = "room-compiler", version.ref = "room" }

[plugins]
ksp = { id = "com.google.devtools.ksp", version.ref = "ksp" }
```

Root `build.gradle.kts`: `alias(libs.plugins.ksp) apply false`.

`app/build.gradle.kts`: apply `alias(libs.plugins.ksp)`, add the three Room deps (`ksp(...)` for the
compiler), and add

```kotlin
ksp { arg("room.schemaLocation", "$projectDir/schemas") }
```

`gradle.properties`: add `android.disallowKotlinSourceSets=false`. **Load-bearing** — see the
toolchain notes in `CLAUDE.md`. Without it the build fails at configuration time.

### 2. Lifecycle Compose bindings — needed by the first ViewModel

The template pulls in `lifecycle-runtime-ktx` but not the Compose bindings. Mealz uses both:

```toml
androidx-lifecycle-viewmodel-compose = { group = "androidx.lifecycle", name = "lifecycle-viewmodel-compose", version.ref = "lifecycleRuntimeKtx" }
androidx-lifecycle-runtime-compose   = { group = "androidx.lifecycle", name = "lifecycle-runtime-compose",   version.ref = "lifecycleRuntimeKtx" }
```

`viewmodel-compose` gives `viewModel(factory = ...)`; `runtime-compose` gives
`collectAsStateWithLifecycle()`. Both are used on every screen in Mealz.

### 3. Java 17

The template set `compileOptions` to Java 11. Mealz is on 17 and nothing here needs 11. Raise both
`sourceCompatibility` and `targetCompatibility` to `JavaVersion.VERSION_17` when the first real code
lands. No `jvmTarget` block is needed — Kotlin follows `compileOptions` under AGP 9's built-in
Kotlin.

### 4. Image loading and capture — **new ground, not inherited**

This is the one place where Reevz Drip genuinely departs from Reevz Mealz. A meal is a name and a
price; a garment is a **photograph**. Mealz has no image handling at all, so there is no existing
pattern to copy and these are real decisions, tracked in `docs/DECISIONS.md`:

- **Image loading.** Compose has no built-in async image loader. The standard answer is **Coil**
  (`io.coil-kt.coil3:coil-compose`), and it is the first dependency this project will add that Mealz
  does not have. Decoding and downsampling bitmaps by hand for a scrolling grid is not a reasonable
  alternative. Needs the user's sign-off under the "explain before adding a dependency" rule.
- **Getting a photo in.** Two routes, and they are different amounts of work:
  - *Photo Picker* (`ActivityResultContracts.PickVisualMedia`) — no runtime permission on any API
    level, backported below 30 via Google Play services. Cheap.
  - *Camera capture* (`ActivityResultContracts.TakePicture` + a `FileProvider`) — needs a provider
    declared in the manifest and an XML paths file. More setup.
- **Where the bytes live.** App-internal storage (`context.filesDir`), with the database holding a
  filename only. Internal storage is private, is included in the app's data directory for backup
  purposes, and disappears cleanly on uninstall. **Never store image bytes in a Room `BLOB`** —
  it bloats the database, slows every query that touches the row, and makes the migration story
  worse.
- **Downsizing on import.** A modern phone camera produces 4–12 MB JPEGs. A wardrobe of 200 garments
  at full resolution is a multi-gigabyte directory on a device with no cloud backup. Re-encode on
  import to something like 1080px on the long edge. Decide the number when the phase is specified.
- **Orientation.** Camera JPEGs carry EXIF rotation that `BitmapFactory` ignores. Coil honours EXIF;
  hand-rolled decoding does not. One more reason for Coil.

### 5. Notifications — only if a phase asks for them

Mealz has a complete, working pattern to copy: `AlarmManager` with a `PendingIntent`, a
`BroadcastReceiver` that posts the notification, a `BootReceiver` on `BOOT_COMPLETED` to re-arm
(alarms do not survive reboot), and `POST_NOTIFICATIONS` + `RECEIVE_BOOT_COMPLETED` in the manifest.
Copy `notify/` from Mealz rather than reinventing it.
